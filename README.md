# Расписание школы (Timetable)

Django-приложение для расписания уроков:
- Публичный просмотр расписания по классу и по учителю — БЕЗ логина.
- Удобный редактор-сетка для завуча — С логином (защищено @login_required).

## Быстрый запуск с тестовыми данными (попробовать за 2 минуты)

Нужен только Python 3 на компьютере, ничего больше не устанавливать (ни nginx, ни Docker).

```bash
# 1. Распаковать архив и зайти в папку
cd timetable_project

# 2. Создать окружение и поставить Django
python3 -m venv venv
source venv/bin/activate          # Windows (cmd): venv\Scripts\activate
pip install -r requirements.txt

# 3. Создать базу и загрузить тестовые данные (2 класса, 3 учителя, готовое расписание)
python manage.py migrate
python manage.py loaddata schedule/fixtures/demo_data.json

# 4. Создать логин для завуча (свой, для входа в редактор)
python manage.py createsuperuser

# 5. Запустить
python manage.py runserver
```

Дальше открыть в браузере:
- **http://127.0.0.1:8000/** — главная, уже с классами 7B и 9A с готовым расписанием
- **http://127.0.0.1:8000/class/7b/** — расписание класса без логина
- **http://127.0.0.1:8000/login/** — вход под логином, который создал на шаге 4
- **http://127.0.0.1:8000/editor/7b/** — редактор сетки (после входа)
- **http://127.0.0.1:8000/admin/** — админка справочников

Сервер работает, пока открыт терминал. Остановить — `Ctrl+C`. Это официальный встроенный dev-сервер Django (`runserver`) — отдельный веб-сервер (nginx/gunicorn) для локальной пробы не нужен, он нужен только для боевого продакшена в интернете.

## Порядок настройки с нуля

1. Зайти в /admin/ под учётной записью завуча (созданной через createsuperuser).
2. Добавить: Классы (SchoolClass), Учителей (Teacher), Предметы (Subject), Кабинеты (Room, необязательно).
3. Добавить "Звонки" (BellSlot) — время начала/конца каждого урока (1, 2, 3... урок), общее для всей школы.
4. Перейти в /editor/ → выбрать класс → для каждой ячейки (день + номер урока) выбрать предмет и учителя → "Сохранить расписание".
5. Расписание сразу появится на публичной странице /class/<slug>/ и /teacher/<slug>/.

## Потоки: одновременный английский и деление на группы

По изменениям в тарификации учителей английского языка урок английского идёт
**одновременно** у нескольких параллелей, а ученики делятся на группы по уровню —
каждую группу ведёт свой учитель:

| Поток | Классы | Групп/учителей |
|---|---|---|
| Английский 5-6 | 5A, 5B, 6A, 6B | 3 |
| Английский 7-8 | 7A, 7B, 8A, 8B | 3 |
| Английский 9-10 | 9A, 9B, 10A, 10B | 3 |
| Английский 11 | 11A, 11B | 3 |

**Конкретных учителей задавать необязательно.** Поток отвечает только за «когда»:
у каких классов английский идёт одновременно. Кто ведёт какую группу — завуч
выбирает сам в `/editor/<класс>/`: у каждой ячейки три списка (основной, 2-й и
3-й учитель). Потоки при этом разводятся по разным дням и урокам, поэтому одного
и того же учителя можно поставить хоть во все потоки сразу — накладки не будет.

### Как это устроено

- **Поток** (`ParallelBlock`) — предмет + список классов (+ необязательный пул
  учителей). Настраивается в админке: `/admin/schedule/parallelblock/`.
- У урока (`Lesson`) кроме основного учителя есть **дополнительные учителя**
  (`co_teachers`) — второй и третий, ведущие свои группы, и ссылка на поток.
- Генератор ставит предмет потока у всех классов потока в **один и тот же день
  и на один и тот же номер урока**, а сдвоенные уроки не разрывает.
- Проверка накладок знает про потоки: учитель потока может одновременно вести
  группы в нескольких классах потока — это не накладка. Но если тот же учитель
  в это же время стоит обычным уроком в другом классе — предупреждение будет.
- Потоки с общими учителями (например, один учитель ведёт и 5-6, и 11)
  автоматически разводятся по разным дням и разным урокам. Если учителя потока
  не заданы, система считает, что английский во всех потоках ведут одни и те же
  люди, и разводит потоки так же — чтобы потом можно было назначить кого угодно
  вручную и не получить накладку.

### Порядок настройки

```bash
# 1. Первый прогон — создаст классы из РУП
python manage.py generate_schedule РУП.xlsx тарификация.xlsx

# 2. Создать потоки (5-6, 7-8, 9-10, 11 — классы А и В)
python manage.py setup_english_blocks

# 3. Перегенерировать расписание — теперь с одновременными уроками
python manage.py generate_schedule РУП.xlsx тарификация.xlsx
```

Дальше открыть `/editor/<класс>/` и выбрать учителей групп руками.

Полезные ключи `setup_english_blocks`:

- `--letters "A,B,C"` — какие буквы классов входят в поток (по умолчанию `A,B`)
- `--subject "Иностранный язык"` — если предмет называется иначе
- `--dry-run` — показать, что будет создано, ничего не записывая
- `--teachers "Аяулым,Сапар,Гульнара"` и `--teachers-11 "Грегори,Сапар,Аяулым"` —
  если хочется сразу проставить учителей во все уроки потока автоматически
- `--clear-teachers` — убрать учителей из потоков и выбирать их вручную

Ключ `generate_schedule --ignore-blocks` строит расписание по старой схеме,
не учитывая потоки.

### Ручная правка в редакторе

В `/editor/<класс>/` у каждой ячейки теперь три выпадающих списка учителей:
основной, второй и третий (для групп). Если класс входит в поток, над таблицей
показывается подсказка с составом потока.

## Проверка по методическим рекомендациям СанПиН РК

При сохранении расписания в редакторе (`/editor/<class>/`) сервер дополнительно проверяет
соответствие рекомендациям приказа Министра здравоохранения РК от 5 августа 2021 года
№ ҚР ДСМ-76 «Санитарно-эпидемиологические требования к объектам образования»:

- **п.73** — сдвоенные уроки (один и тот же предмет + учитель на двух уроках подряд)
  не допускаются в начальной школе (1–4 классы).
- **Приложение 4** (шкала трудности предметов) — сложные предметы не рекомендуется
  ставить первым или последним уроком дня, а также группировать несколько сложных
  предметов в один день.
- Рекомендуемое распределение недельной нагрузки — наибольшее число уроков должно
  приходиться на вторник/среду (биоритмологический оптимум работоспособности), а не
  на понедельник/пятницу.

Эти проверки — **предупреждения, не блокировка** (в отличие от занятости учителя/кабинета,
которая блокирует сохранение). Чтобы они срабатывали, нужно заполнить два дополнительных поля
в админке:

- у **класса** (`/admin/schedule/schoolclass/`) — поле «Параллель (класс), 1-12»,
  например `4` для класса «4A» (нужно для проверки правила о сдвоенных уроках в начальной школе);
- у **предмета** (`/admin/schedule/subject/`) — поле «Балл трудности (СанПиН РК), 1-5»,
  где 1 — самый лёгкий предмет (физкультура, музыка, труд), 5 — самый сложный
  (математика, языки, физика).

Оба поля необязательны — если не заполнить, соответствующая проверка просто не будет
выполняться для этого класса/предмета.

**Важно:** это вспомогательный инструмент, помогающий не забыть об основных требованиях
при составлении расписания, а не полноценная система юридической проверки на соответствие
СанПиН. Приказ периодически меняется (последняя проверенная редакция — по состоянию на
01.09.2025), и часть норм (например, точные предельные значения недельной нагрузки по
классам из Приложения 3) в это приложение сознательно не заложена, так как эти цифры
зависят от конкретного рабочего учебного плана школы. Финальную проверку соответствия
расписания всем нормам должен делать завуч самостоятельно.

## Деплой в интернет на постоянку (Docker + nginx + HTTPS)

В проекте уже готовы: `Dockerfile`, `docker-compose.yml`, `nginx.conf`, `.env.example`.
Схема та же, что для MetalGid — Django (gunicorn) за nginx, только тут используется
SQLite вместо Postgres (для расписания школы этого достаточно).

### Что нужно заранее

1. **VPS** (например, PS.kz, Hetzner, DigitalOcean) с Docker и docker-compose.
2. **Домен**, указывающий A-записью на IP этого VPS (например `timetable.iss-astana.kz`).

### Шаги

```bash
# 1. Скопировать проект на сервер (git clone, scp или просто загрузить zip и распаковать)

# 2. Создать .env из примера и заполнить
cp .env.example .env
nano .env
#   - DJANGO_SECRET_KEY — сгенерировать: python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
#   - DJANGO_ALLOWED_HOSTS=твой-домен
#   - DJANGO_CSRF_TRUSTED_ORIGINS=https://твой-домен

# 3. Вписать домен в nginx.conf вместо YOUR_DOMAIN (в обоих местах)
nano nginx.conf

# 4. Запустить
docker compose up -d --build

# 5. Создать логин завуча внутри контейнера
docker compose exec web python manage.py createsuperuser

# (опционально) загрузить тестовые данные для проверки
docker compose exec web python manage.py loaddata schedule/fixtures/demo_data.json
```

На этом этапе сайт уже должен открываться по `http://твой-домен/` (пока без HTTPS).

### Включить HTTPS (бесплатный сертификат Let's Encrypt)

```bash
docker run -it --rm \
  -v $(pwd)/nginx_certbot_www:/var/www/certbot \
  -v timetable_project_certbot_conf:/etc/letsencrypt \
  certbot/certbot certonly --webroot -w /var/www/certbot \
  -d твой-домен --email твой-email --agree-tos --no-eff-email
```

После успешного получения сертификата: раскомментировать блок `server { listen 443 ssl; ... }`
в `nginx.conf`, перезапустить `docker compose restart nginx` — сайт заработает по `https://`.

### Дальнейшая поддержка

- Обновление кода: `git pull && docker compose up -d --build`
- Бэкап базы: файл лежит в Docker-volume `db_data` — можно скопировать через
  `docker compose exec web cat /app/data/db.sqlite3 > backup.sqlite3`
- Логи: `docker compose logs -f web`

## Исправления: учителя английского, сдвоенные уроки, класс 11С

Актуальные исходные файлы:
`РУП_2026-2027__EIS_fin.xlsx` и `тарификация_Edville_2026-2027_учгод_1_пг_final_vol_2.xlsx`.

### Что было сломано

1. **Предмет называется «English», а код искал «английск»/«иностранн».** Это и
   есть причина, по которой английский не ставился сдвоенными уроками:
   `pair_subjects_for()` не признавала «English» английским, поэтому 6 часов
   раскладывались шестью одиночными уроками. По той же причине предмет получал
   средний балл трудности 3 вместо 5, не считался языком в проверке начальной
   школы и мог оказаться последним уроком дня. И в тарификации строки
   «English 8А 9В 11С» / «Speaking 1A 2A 3A» не сопоставлялись ни с одним
   предметом — учителя английского вообще не попадали в расписание.
2. **Коды классов через запятую терялись.** Регулярка `CLASS_RUN_RE` разрешала
   между классами только пробел и знала только буквы `А В A B`. Строки вида
   «English 6А, 7А, 9А» обрывались на первой запятой, а меткой предмета для
   остатка становилась сама запятая.
3. **Буква «С» не входила в регулярки.** Упоминания 11С отбрасывались, а код
   «11С» прилипал к названию следующего предмета («11с нвп», «11с графика»).
   Плюс `DEFAULT_LETTERS = ["A", "B"]` не пускал 11С в потоки английского,
   из-за чего редактор считал любого учителя английского занятым в 11А/11В и
   отказывался сохранять ячейку 11С.
4. **Учителя потока не делились по группам** — основным во всех классах потока
   ставился `teachers[0]`, один и тот же человек везде.
5. **Несколько учителей одного предмета затирали друг друга** — строка
   «Speaking 1A 2A 3A» перезаписывала «English 1А 2А 3А».

### Что изменено

- `import_rup.py` — добавлены `ENGLISH_SUBJECT_KEYWORDS` и `is_english_subject()`;
  через них теперь идут сдвоенные уроки, балл трудности (English = 5) и запрет
  ставить предмет последним уроком.
- `generate_schedule.py` — «English»/«Speaking» считаются языками в проверке
  начальной школы; несколько учителей на пару (предмет, класс) — первый
  основной, остальные в `co_teachers`; учителя потока раздаются по классам
  по кругу; добавлен ключ `--clone-class` на случай класса, которого нет в РУП.
- `assign_teachers.py` — регулярки классов принимают любые заглавные буквы
  (кириллица, казахские, латиница) и запятую/точку с запятой как разделитель;
  метки `english` / `speaking` / `английский язык` ведут на предмет `English`;
  добавлены `основы права`, `графика`, исправлено название НВП.
- `setup_english_blocks.py` — `DEFAULT_LETTERS = ["A", "B", "C"]`.
- `views.py` — урок того же предмета в другом классе потока не считается
  накладкой, даже если у него не проставлено поле `parallel_block`.
- Новая команда `check_assignments` — проверка «класс → учитель» без записи в БД.

### Порядок запуска

```bash
RUP="РУП_2026-2027__EIS_fin.xlsx"
TAR="тарификация_Edville_2026-2027_учгод_1_пг_final_vol_2.xlsx"

# 1. Посмотреть, кому что достаётся (ничего не меняет)
python manage.py check_assignments "$RUP" "$TAR" --subject English

# 2. Построить расписание (создаст в том числе класс 11С)
python manage.py generate_schedule "$RUP" "$TAR"

# 3. Создать потоки английского (5-6, 7-8, 9-10, 11 — с буквами A, B, C)
python manage.py setup_english_blocks

# 4. Перегенерировать — уже с учётом потоков
python manage.py generate_schedule "$RUP" "$TAR"
```

Шаг 4 нужен потому, что потоки ссылаются на классы, а классы создаются только
на первом прогоне.

### Что осталось поправить в исходных файлах (это не код)

- **4А отсутствует в тарификации целиком** — нет ни строки английского, ни
  классного руководителя. Все 12 предметов класса останутся с заглушкой
  «Не назначен».
- **Художественный труд в 5А и 6А** никому не назначен.
- У Егинбая Адиля в тарификации остались **«Закон и порядок»** (9А, 10А, 10В,
  11А, 11В, 11С) и **«Основы Конституции»** (5А-8А) — таких предметов в новом
  РУП больше нет, эти 10 записей игнорируются.
